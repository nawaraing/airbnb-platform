# 01. 제품 개요

## 1. 배경

기존 도구(첨부 스크린샷)는 PC에 설치해서 쓰는 형태입니다. 제공하는 기능은 다음과 같습니다.

- 에어비앤비 로그인 세션으로 예약·게스트·정산 정보 동기화
- 대시보드 (이번 달 예약/매출/순수익, 다음 청소, 최근 활동 로그, 연동 상태)
- 예약·수익 캘린더 (예약 막대, 일별 요금, 퇴실=청소일, 청소비 자동 지출 합산)
- 당일 공실 자동 요금 인하 (시간대·주기·인하액·최저가 설정)
- 다음달 공실 자동 가격 설정 ('비슷한 숙소 최대금액 − 할인액', 매일 실행)
- 청소직원 카카오톡 일정 안내 (PC 카카오톡 UI를 자동 조작해 발송)
- 고유코드 인증 (사용자 라이선스)

### 기존 방식의 한계

| 한계 | 결과 |
|------|------|
| PC가 켜져 있고 프로그램이 실행 중이어야 자동화가 동작 | 외출·취침 중 요금 인하나 동기화가 멈춤 |
| PC 카카오톡 UI 자동 조작 | 발송 중 마우스·키보드를 쓸 수 없고, 카카오톡 UI가 바뀌면 깨짐 |
| PC 한 대에 종속 | 모바일에서 확인·조작 불가, 공동 운영자와 공유 불가 |
| 게스트 응대 기능 없음 | 문의 응답·안내 메시지는 여전히 수작업 |
| 요금 자동화가 '공실 할인' 2종뿐 | 성수기·주말·연휴 같은 기간별 요금은 수동 관리 |

### 웹앱 전환으로 얻는 것

- 서버에서 자동화가 상시 실행됩니다. PC를 꺼도 됩니다.
- 모바일 포함 어디서든 확인하고 승인할 수 있습니다.
- CS 메시지와 기간별 요금처럼 새 자동화를 추가할 수 있습니다.
- **여러 호스트가 쓰는 SaaS**로 운영합니다(확정).
- 에어비앤비 외 채널로 확장할 수 있습니다(계획 확정, M6 이후).

## 2. 목표와 비목표

### 목표

1. 반복 업무(게스트 응대, 요금 조정, 청소 일정 공유, 정산 집계)를 자동화해 호스트의 일일 운영 시간을 줄입니다.
2. 사용자 PC 상태와 관계없이 자동화가 동작합니다.
3. 외부에 영향을 주는 모든 자동 동작(요금 변경, 메시지 발송)은 **미리 볼 수 있고, 이력이 남고, 즉시 멈출 수 있어야** 합니다.
4. 기존 도구 기능을 동등 이상으로 제공합니다. 기존 사용자가 옮겨왔을 때 잃는 기능이 없어야 합니다.
5. 다채널 확장을 전제로 설계합니다. 운영의 기준 단위는 채널 리스팅이 아니라 실제 **숙소**입니다([10](10-multi-channel.md)).

### 비목표 (초기 범위 밖)

- MVP 단계의 에어비앤비 외 채널 연동. 다른 채널은 M6부터 단계적으로 붙이며, 데이터 모델과 커넥터는 처음부터 다채널 구조로 만듭니다.
- 세무 신고, 전자세금계산서 발행
- 게스트용 직접 예약 사이트
- 스마트락·IoT 연동 (후보 기능)
- 자체 동적 가격 모델(수요 예측). 시장 데이터는 에어비앤비가 제공하는 '비슷한 숙소' 정보를 사용합니다.

## 3. 사용자

| 사용자 | 특징 | 핵심 니즈 |
|--------|------|-----------|
| **소규모 호스트** (주 타깃) | 숙소 1~5개, 본인이 직접 운영, 청소는 외부 직원 1~2명 | 손 덜 가는 응대·요금 관리, 모바일 확인 |
| 중규모 운영자 | 숙소 5~30개, 공동 운영자·매니저 있음 | 숙소 일괄 설정, 팀 권한, 리포트 |
| 청소 직원 | 앱 계정 없음, 카카오톡 사용 | 정확한 청소 일정, 변경 즉시 통보 |

|------|------|------|----------|
| 계정 | 회원가입/로그인(카카오·이메일), 워크스페이스 | 기존 '고유코드 인증' 대체 | MVP |
| 연동 | 에어비앤비 계정 연결(원격 로그인), 숙소 선택·별칭, 연동 상태 | 기존 | MVP |

| 예약·수익 | 월 캘린더, 예약 상세, 정산 기준 매출, 지출(청소비 자동 합산·수동 지출), 순수익 | 기존+개선 | MVP |
| 요금 자동화 | **기간별 요금 규칙** (기간·요일·남은 일수 조건) | **신규 (요청 2)** | MVP |
| | 당일 공실 단계 인하 | 기존 | MVP |

| | **AI 문의 응답** (분류 + 답변 초안, 승인/자동 발송) | **신규 (요청 1)** | MVP |

| 운영 | 팀 멤버·권한, 구독 결제, 리포트 내보내기 | 신규 | 후속 |

## 5. 용어집

| 용어 | 정의 |
|------|------|
| 워크스페이스 | 데이터 소유 단위. 호스트 1명 또는 운영팀 1개입니다. 모든 데이터는 워크스페이스에 속합니다. |
| 채널 | 숙소를 판매하는 창구. `airbnb`, 후속 채널, `ical`(캘린더 연동만), `direct`(직접 예약) |
| 연결(Connection) | 워크스페이스에 연결된 채널 계정 1개(예: 에어비앤비 호스트 계정)와 그 세션 |
| 숙소(Unit) | 실제 운영 공간 1개. 사용자가 붙인 **별칭**(예: `DMC역`)으로 표시합니다. 요금 규칙, 청소, 지식베이스 같은 운영 설정은 모두 숙소에 붙습니다. |
| 채널 숙소(Channel listing) | 숙소를 특정 채널에 올린 리스팅(예: 에어비앤비 리스팅 1개). 숙소 1개에 채널별로 여러 개가 연결될 수 있습니다. MVP에서는 1:1입니다. |
| 예약(Reservation) | 게스트 1건의 숙박. 체크인일 ~ 체크아웃일 |
| 박(Night) | 요금 단위. 체크인일부터 체크아웃 전날까지의 각 날짜 |
| 정산(Payout) | 에어비앤비가 호스트에게 지급하는 금액(호스트 수수료 차감 후). **정산일**은 지급일입니다. |
| 공실 | 예약도 차단도 되지 않아 판매 가능한 날짜 |
| 청소일 | 체크아웃일. 같은 날 다음 체크인이 있으면 **당일 입실(Back-to-back)** 이라고 합니다. |
| 희망 요금 | 요금 규칙으로 계산한, 해당 날짜에 있어야 할 요금 |
| 적용(Push) | 희망 요금을 실제 에어비앤비 캘린더에 반영하는 동작 |
| 커넥터 | 외부 플랫폼(에어비앤비)과 통신하는 모듈. 나머지 코드는 커넥터의 채널 중립 DTO만 다룹니다. |
| 킬 스위치 | 워크스페이스나 숙소 단위로 모든 자동 부작용(요금 변경·발송)을 즉시 멈추는 스위치 |
| 지식베이스 | 숙소별 안내 정보(체크인 방법, 와이파이, 주차 등). AI 답변의 근거가 됩니다. |

## 6. 성공 지표

| 지표 | 정의 | 초기 목표 |
|------|------|-----------|
| 첫 응답 시간 | 게스트 메시지 → 첫 답장(자동 또는 승인) 시간의 중앙값 | 10분 이내 |
| 초안 무수정 승인율 | AI 초안 중 수정 없이 발송된 비율 | 60% 이상 |
| 당일 인하 판매 | 당일 인하가 진행 중일 때 들어온 당일 예약 수 | 측정 후 기준 설정 |
| 자동화 활성 숙소 비율 | 자동화를 1개 이상 켠 숙소 / 전체 숙소 | 70% 이상 |
| 동기화 성공률 | 성공한 동기화 / 전체 시도 | 98% 이상 |
| 재로그인 빈도 | 연결 1개당 월 평균 재로그인 요구 횟수 | M0에서 측정 |
