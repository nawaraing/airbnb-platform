# 07. 청소 운영

## 1. 청소 작업 산출

청소 작업은 숙소의 예약 데이터(다채널이면 모든 채널의 예약, 직접 예약 포함)에서 자동으로 만듭니다. 호스트가 따로 입력하지 않습니다.

### 1.1 규칙

```
확정 예약 R마다 (취소 제외):
  task.date          = R.check_out
  task.window_start  = R.check_out + 숙소 체크아웃 시각 (기본 11:00)
  next               = 같은 숙소에서 check_in ≥ R.check_out 인 가장 이른 확정 예약
  next.check_in == R.check_out → same_day_turnover = true,  window_end = 그날 체크인 시각 (기본 15:00)
  next 있음 (다른 날)          → same_day_turnover = false, window_end = next.check_in + 체크인 시각
  next 없음                    → window_end = null
  task.staff = 숙소의 기본 담당 직원
  task.cost  = 날짜별 수정값 ?? 숙소 기본 청소비 (예: 27,000원)
```

- **수동 청소 작업**: 호스트 본인 사용 후, 정기 대청소 등 예약과 관계없는 청소도 직접 추가할 수 있습니다.
- 상태: `scheduled` → `notified`(직원에게 안내됨) → `done`(직원 완료 체크, 후속) / `cancelled`(예약 취소)
- 예약 이벤트(생성·변경·취소)가 오면 해당 숙소의 작업을 다시 계산합니다. 바뀐 작업이 있으면 변경 알림(§4.2)을 보냅니다.

### 1.2 청소비 지출 연동

- 취소되지 않은 청소 작업마다 지출(`expenses`, `source = cleaning_task`)을 하나씩 만듭니다. 날짜는 청소일, 금액은 `task.cost`입니다.
- 비용을 수정하면 지출도 따라 바뀌고, 작업이 취소되면 지출을 삭제합니다.
- 월 집계에는 해당 월의 청소비를 **예정 건까지 포함**해서 반영합니다. 대시보드에서는 예정분을 별도로 표시합니다.

## 2. 일정 메시지 자동 작성

기존 '일정 자동작성' 규칙을 재현하고 정리합니다.

- 기간: 기준일(오늘) ~ 21일 후
- 섹션
  - **확정 청소**: 청소일, 시작 시각, 다음 입실(당일 입실이면 강조)
  - **다음 입실**: 체크인 일시, 인원, 박 수. 수건·침구 준비량 판단용이며 게스트 이름은 넣지 않습니다.
  - **미정일**: 기간 안의 공실 박. 예약이 들어오면 청소일이 새로 생길 수 있는 날입니다.

### 예시 (첨부 캘린더의 DMC역, 2026-10-04 기준)

```
🧹 청소 일정 안내  (2026-10-04 (일) 기준)
────────────────
■ 확정 청소
· 2026-10-05 (월) 11:00 청소필요 → 다음 입실 10/06 (화) 15:00
· 2026-10-11 (일) 11:00 청소필요 → 다음 입실 10/14 (수) 15:00
· 2026-10-18 (일) 11:00 청소필요 → 다음 입실 10/22 (목) 15:00

■ 다음 입실
· 10/06 (화) 15:00 · 1명 · 5박
· 10/14 (수) 15:00 · 3명 · 4박
· 10/22 (목) 15:00 · 6명 · 6박

■ 미정일 (예약이 들어오면 다시 알려드릴게요)
· 10/05 (월) 1박
· 10/11 (일) ~ 10/13 (화) 3박
· 10/18 (일) ~ 10/21 (수) 4박
```

- 렌더링은 `packages/core/cleaning/compose.ts`(순수 함수)에서 합니다. 화면 미리보기와 자동 발송이 같은 함수를 씁니다.
- 수신자가 여러 숙소를 맡고 있으면 숙소별 블록을 이어 붙입니다. 화면에서는 숙소 하나만 고를 수도 있습니다.
- 호스트는 발송 전에 메시지를 자유롭게 편집할 수 있습니다(기존과 동일).

## 3. 발송 채널

기존 도구는 PC 카카오톡 UI를 자동 조작해서 보냈습니다. 서버에서는 이 방식을 쓸 수 없습니다.

| 채널 | 자동 발송 | 비용 | 제약 | 용도 |
|------|-----------|------|------|------|
| **카카오 알림톡** (딜러사 API) | 가능 | 건당 소액 (딜러사 요금) | 플랫폼 운영자의 카카오톡 채널과 비즈니스 인증 필요, **템플릿 사전 심사**, 정보성 메시지만, 본문 1,000자 제한 | 자동 발송 기본 채널 |
| SMS/LMS | 가능 | 알림톡보다 비쌈 | 발신번호 사전 등록 | 알림톡 실패 시 대체 발송 |
| **카카오톡 공유** (Kakao JS SDK) / Web Share API | 불가 (사람이 누름) | 무료 | 호스트가 매번 친구·채팅방 선택 | 수동 발송 기본, 알림톡 미설정 시 |
| 복사 | 불가 | 무료 | — | 어디든 붙여넣기 |
| 로컬 에이전트의 PC 카톡 조작 (기존 방식) | PC가 켜져 있을 때만 | 무료 | 설치 필요, UI 변경에 취약 | 후순위 옵션 ([04 §11](04-airbnb-integration.md#11-대체-드라이버-d-로컬-에이전트-메모)) |

### 결정 (확정: 알림톡 도입)

- **자동 발송은 알림톡, 실패하면 LMS로 대체 발송**합니다. 발신 주체는 플랫폼의 카카오톡 채널(예: "○○ 청소알림")입니다. 호스트마다 채널을 만들 필요가 없습니다. 메시지에는 숙소 별칭과 호스트 이름을 넣어 누가 보낸 안내인지 알 수 있게 합니다.
- **수동 발송은 카카오톡 공유**를 씁니다. 기존처럼 '내 카톡으로 직원에게 보내기' 경험을 유지하면서 무료입니다.
- 직원 정보의 `카카오톡 표시 이름`은 기존 방식(채팅방 검색)에만 필요했습니다. 이제는 선택 입력으로 두고, 필수는 휴대폰 번호입니다.

### 알림톡 템플릿 (심사용 초안)

일정처럼 길이가 변하는 내용을 변수 하나에 통째로 넣으면 심사에서 반려될 수 있습니다. 그래서 두 안을 함께 신청합니다.

**A안 (본문형)**: 일정 전문을 넣습니다.

```
[#{숙소명}] 청소 일정 안내
#{호스트명}님이 보낸 #{기준일} 기준 3주 일정입니다.

#{일정}

일정이 바뀌면 다시 알려드릴게요.
[버튼] 전체 일정 보기 → https://<도메인>/s/#{토큰}
```

**B안 (요약형, A안 반려 시)**: 요약만 넣고 상세는 링크로 봅니다.

```
[#{숙소명}] 청소 일정 안내
가장 가까운 청소: #{다음청소일시}
향후 3주 확정 청소: #{건수}건
자세한 일정은 아래 버튼에서 확인해 주세요.
[버튼] 일정 보기 → https://<도메인>/s/#{토큰}
```

**변경 알림**:

```
[#{숙소명}] 청소 일정 변경
#{변경내용}
[버튼] 일정 보기 → https://<도메인>/s/#{토큰}
```

`#{변경내용}` 예: `추가: 10/12 (월) 11:00 청소 (당일 15:00 입실 2명)` / `취소: 10/18 (일) 청소`

B안과 변경 알림은 링크가 핵심이므로 직원용 일정 페이지(§6)의 읽기 전용 버전을 M3에 함께 만듭니다.

## 4. 자동 발송 시나리오

### 4.1 정기 안내

- 직원별로 설정합니다: 매일 또는 지정 요일, 발송 시각(기본 20:00), 기간(기본 21일)
- 옵션 **"바뀐 게 있을 때만"**: 마지막 발송 스냅샷과 비교해서 차이가 없으면 보내지 않습니다.

### 4.2 변경 알림

- 예약 이벤트로 직원 담당 숙소의 **향후 14일** 청소 작업이 추가·취소·시간 변경되면 보냅니다.
- 10분 디바운스로 여러 변경을 묶어 한 번에 보냅니다.
- 마지막으로 보낸 스냅샷(`cleaning_digest_snapshots`)과 비교해 바뀐 부분만 담습니다.

### 4.3 당일 리마인드 (선택)

청소 당일 08:00에 그날 작업만 보냅니다.

### 4.4 수동 발송

기존 화면 흐름 그대로입니다. 받는 사람과 숙소를 고르고 `일정 자동작성` → 편집 → `알림톡 발송` / `카카오톡 공유` / `복사` 중 선택합니다.

## 5. 발송 처리

```
notify.send(notification):
  킬스위치 확인 (호스트 대상 긴급 알림은 예외)
  outbound_notifications (status = queued, idempotency_key)
  알림톡 요청 → 성공: sent → 결과 웹훅: delivered | failed
  실패 & 대체 발송 허용 → LMS 발송 → fallback_sent
  activity_logs 기록 ("김민혁님에게 청소 일정 안내 발송 (알림톡)")
  관련 cleaning_tasks.status = notified
```

- 발송 내역 탭에는 일시, 수신자, 채널, 상태, 본문을 보여줍니다.
- 실패하면 호스트에게 알리고 `카카오톡 공유로 보내기` 버튼을 띄웁니다.

## 6. 직원용 일정 페이지 (`/s/[token]`)

| 단계 | 기능 |
|------|------|
| M3 (읽기 전용) | 담당 숙소의 향후 3주 청소 일정, 다음 입실 인원, 숙소 메모(비품 위치 등) |
| 후속 | `청소 완료` 버튼 + 사진 업로드(Supabase Storage) → 호스트 알림, 비품 부족 신고, 작업별 메모 |

- 토큰은 직원별 무작위 32바이트 값이고 DB에는 해시만 저장합니다. 호스트가 언제든 폐기하고 재발급할 수 있습니다.
- 로그인 없이 열리므로 게스트 이름, 정산액, 도어락 비번은 표시하지 않습니다. 비번이 필요한 직원용으로는 '직원 공개' 표시된 지식베이스 항목만 보여줍니다.

## 7. 직원 관리

| 필드 | 필수 | 비고 |
|------|------|------|
| 이름 | ○ | |
| 휴대폰 번호 | ○ (알림톡/SMS용) | |
| 카카오톡 표시 이름 | — | 로컬 에이전트 방식용 (기존 호환) |
| 담당 숙소 | ○ | 여러 개 가능, 숙소별 기본 담당 1명 |
| 정기 안내 설정 | — | §4.1 |
| 메모 | — | |

- 직원 연락처는 호스트가 입력합니다. 직원에게 수집 사실을 알리는 책임이 호스트에게 있다는 점을 이용약관에 명시하고, 모든 메시지에 수신 거부 방법을 넣습니다.
- 직원을 삭제하면 담당 작업의 담당자는 비우고, 공유 토큰은 폐기합니다.

## 8. 알림톡 준비 작업

알림톡 도입이 확정됐으므로 다음을 M0에 시작합니다. 템플릿 심사와 계약에 시간이 걸려 개발보다 먼저 끝나야 합니다.

1. 플랫폼 운영 주체의 사업자 등록 정보 준비
2. 카카오톡 채널 개설과 비즈니스 인증. 채널명은 서비스명이 정해진 뒤 확정합니다. 가칭으로 개설한 뒤 이름을 바꿀 수 있는지도 확인합니다.
3. 딜러사(Solapi 등) 계약, 발신 프로필 등록, LMS 대체 발송용 발신번호 사전 등록
4. 템플릿 신청: 청소 일정 A/B안, 변경 알림, 호스트용(승인 요청, 긴급 문의, 세션 만료, 이중 예약 감지)

## 9. 결정 필요

- 정기 안내 기본값(매일 20:00, "바뀐 게 있을 때만" 켬)
- 월 집계에서 예정 청소비 포함 여부(포함 제안)
