1# 09. 로드맵·리스크·오픈 이슈

## 1. 마일스톤

기간은 팀 규모가 정해진 뒤에 추정합니다. 이 문서는 순서와 완료 기준만 정합니다.

### M0. 기술 검증 (스파이크)

가장 큰 불확실성인 에어비앤비 연동([04](04-airbnb-integration.md))의 기술적 실현성을 먼저 확인합니다. 연동 방식(C)과 약관 리스크 감수는 확정됐고, 기존 도구 소스가 없어 커넥터는 처음부터 만듭니다.

- [ ] 연산별 호스트 웹 내부 요청 분석과 기록(`NOTES.md`), 응답 fixture 녹화 ([04 §4.2](04-airbnb-integration.md#42-데이터-취득-순서))
- [ ] 서버 워커에서 원격 로그인(라이브 뷰)으로 2단계 인증까지 통과
- [ ] 커넥터 연산 전부 1회 이상 성공: 숙소·예약·정산·캘린더·시장가 읽기, 요금 쓰기(+원복), 메시지 읽기·발송
- [ ] 30분 주기 동기화를 7일간 돌려 세션 유지 기간과 보안 확인 발생 여부를 측정
- [ ] 컨텍스트당 메모리, 동기화 1회 소요 시간 측정 → 워커 용량 산정
- [ ] 원격 로그인 구현 방식 비교(직접 구현 vs 관리형 원격 브라우저)
- [ ] (병행) 알림톡 준비: 카카오톡 채널 개설, 딜러사 계약, 템플릿 심사 신청 ([07 §8](07-cleaning-ops.md#8-알림톡-준비-작업))
- [ ] (병행) 법률 검토 의뢰: 이용약관, 위험 고지·동의 문구, 책임 범위(면책) ([04 §10](04-airbnb-integration.md#10-약관법적-리스크))

**완료 기준**: 모든 연산 성공. 7일 동안 강제 재로그인이 2회 이하. 보안 확인이 발생하지 않았거나, 발생해도 재로그인 흐름으로 복구 가능.
**실패 시**: 드라이버 D(로컬 에이전트) 또는 E(채널 매니저 경유)로 방향을 바꾸고 03·04 문서를 개정합니다.

### M1. 기반 + 기존 기능(읽기)

- 모노레포, Supabase 스키마(숙소/채널 숙소 분리, MVP는 1:1), 인증(카카오/이메일), 워크스페이스
- 에어비앤비 연결 온보딩, 연동 상태, 세션 헬스체크
- 동기화(자동/수동), 도메인 이벤트, 활동 로그(Realtime)
- 대시보드 KPI(정산일/숙박일 기준), 예약·수익 캘린더, 예약 상세, 예약 목록
- 지출: 청소 작업 산출 → 청소비 자동 지출, 수동·반복 지출, 월 수익 탭

**완료 기준**: 기존 도구의 대시보드·예약·수익 화면과 같은 숫자가 나옵니다. 같은 계정으로 양쪽 결과를 대조합니다.

### M2. 요금 자동화

- `packages/core/pricing` 해석 엔진과 단위 테스트(05 §2.3 예시 포함)
- 적용 파이프라인(아웃박스, read-after-write, 멱등), 변경 이력, 되돌리기
- 당일 인하(상태 머신, tick), 공실 시장가(스냅샷, 이상치), **기간별 규칙**(프리셋, 공휴일 데이터)
- 미리보기, 안전장치, 킬 스위치, 시뮬레이션 모드, 사전 점검(스마트 요금, 당일 예약 마감)

**완료 기준**: 테스트 계정에서 시뮬레이션 모드 24시간 → 실적용 72시간 동안 한계 위반 0건, 의도하지 않은 변경 0건.

### M3. 청소 운영

- 청소 일정 화면, 직원 관리, 일정 메시지 자동 작성(기존 규칙 재현)
- 카카오톡 공유·복사, 알림톡 발송 + LMS 대체 발송, 발송 내역
- 정기 안내, 변경 알림, 직원용 일정 페이지(읽기 전용)

### M4. CS 메시지

- 메시지 동기화, 인박스(번역 포함), 수동 답장
- 예약 메시지 템플릿, 스케줄링, 발송
- 지식베이스(+비밀값), AI 초안(승인 모드), 정책 엔진, 키워드 안전망
- 평가셋 구축 → 모델과 effort 결정 → 정보성 분류 자동 발송 개방
- (선택) 이메일 트리거로 새 메시지 감지

**완료 기준**: 평가셋에서 민감·긴급 누락률 0%. 베타 호스트 2주 운영 동안 초안 무수정 승인율 60% 이상.

### M5. 베타 출시 준비

- 이용약관, 개인정보처리방침(국외 이전, 처리 위탁 고지), 연결 시 위험 고지·동의
- 운영 대시보드(서킷 상태, 잡 실패율, 세션 만료율), 카나리 계정 상시 운영
- 모바일 최적화(승인·요금 수정 한 손 조작), 온보딩 다듬기
- 구독 결제(베타 이후 유료 전환 시)

### M6. 멀티채널 1단계 ([10](10-multi-channel.md))

- 숙소-채널 매핑 UI(자동 제안 + 확인)
- iCal 허브: 채널 숙소별 내보내기 URL, 다른 채널 iCal 가져오기
- 직접 예약 입력
- 가용성 동기화(에어비앤비 차단 쓰기 포함), 루프 방지, 이중 예약 감지와 긴급 알림
- 인박스·캘린더 채널 배지, 채널별 매출 분해

**완료 기준**: 테스트 숙소에서 iCal 채널 예약 → 에어비앤비 차단 반영까지 걸리는 시간을 측정하고 고지합니다. 취소 시 우리가 막은 날짜만 해제됩니다(호스트 차단 유지).

### M7~. 채널별 커넥터

대상 채널이 정해지면 채널마다 연동 방식을 조사(04 §2와 같은 평가)한 뒤 커넥터를 구현합니다. 채널별 가격 조정, 메시지 통합, 채널별 정산이 여기에 포함됩니다.

### 이후 후보

팀 멤버·권한, 직원 완료 체크·사진, 고아 날짜 할인, 기간별 최소 숙박일, 리뷰 자동 작성, 리포트·세무 자료 내보내기, 로컬 에이전트 드라이버

> **순서 조정**: 요청 우선순위는 CS 자동화가 1번입니다. CS를 먼저 원하면 M4를 M2 앞으로 옮기거나 병행할 수 있습니다. 메시지 읽기·발송 연산은 M0에서 이미 검증하므로 의존성 문제는 없습니다. 기존 도구를 이미 쓰고 있다면 M1~M3(기존 기능)을 먼저 끝내야 도구를 갈아탈 수 있다는 점은 고려해야 합니다.
