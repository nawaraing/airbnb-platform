# 호스트 운영 플랫폼 — 설계 문서

에어비앤비 호스트가 하루에 반복하는 운영 업무를 웹앱 하나로 자동화하는 플랫폼입니다.
자동화 대상은 게스트 응대, 요금 조정, 청소 일정 공유, 정산 집계입니다.
기존 데스크톱 도구(첨부 스크린샷)의 기능을 웹으로 옮기고, 두 기능을 새로 더합니다.

- **CS 메시지 자동화** (신규)
- **기간별 요금 자동화** (신규)

> 프로젝트명 `airbnb-platform`은 저장소 이름일 뿐입니다. 서비스명에는 'Airbnb/에어비앤비'를 넣지 않는 것을 권장합니다([09-roadmap.md](09-roadmap.md) 오픈 이슈 참고).

## 핵심 설계 결정 요약

| 주제 | 결정 | 상태 | 근거 문서 |
|------|-----------|------|-----------|
| 서비스 형태 | 다수 호스트 대상 SaaS (워크스페이스 단위 멀티테넌시) | **확정** | 01, 08 |
| 채널 범위 | MVP는 에어비앤비만 연동합니다. 다른 채널은 M6부터 붙입니다. | **확정** (대상 채널은 미정) | 10 |
| 숙소 모델 | 숙소(unit)와 채널 숙소(channel listing)를 분리합니다. 운영 설정은 숙소에 붙습니다. MVP는 1:1입니다. | 확정 (다채널 계획에 따름) | 08, 10 |
| 에어비앤비 연동 | 서버 워커가 호스트 세션으로 브라우저를 자동화합니다. 로그인은 '원격 로그인 창'에서 호스트가 직접 합니다. | **확정** (약관 리스크 감수). M0에서 기술적 실현성 검증 | 04 |
| 웹/워커 분리 | Next.js(UI·API)와 상시 실행 Node 워커(Playwright·스케줄러)로 나눕니다. | 제안 | 03 |
| DB·인증 | Supabase(Postgres, Auth+카카오 로그인, Realtime, RLS) | 제안 | 03, 08 |
| 잡 큐 | pg-boss(Postgres 기반)를 씁니다. Redis는 두지 않습니다. | 제안 | 03 |
| 요금 계산 | 희망 상태를 계산하고 현재값과의 차이만 적용합니다(멱등). 우선순위는 레이어로 정합니다. | 제안 | 05 |
| 청소 카톡 | 자동 발송은 알림톡+SMS 대체, 수동 발송은 카카오톡 공유입니다. PC 카톡 조작은 제외합니다. | **확정** (알림톡 도입, 준비는 M0 시작) | 07 |
| 서비스명 | 'Airbnb/에어비앤비'를 넣지 않습니다. | **미정**. 출시 전, 카카오톡 채널명 확정 전에 결정 | 09 |
| CS AI | 분류와 답변 초안을 한 번의 호출로 받습니다(구조화 출력). 민감 정책은 코드로 강제하고, 기본 모드는 '초안 후 승인'입니다. | 제안 | 06 |

## 문서 작성 규칙

- 확정되지 않은 결정에는 **(제안)** 또는 **(결정 필요)** 를 붙입니다. 결정되면 이 표와 해당 문서를 함께 갱신합니다.
- 금액은 원(정수), 시각은 숙소 시간대(기본 `Asia/Seoul`) 기준으로 씁니다.
- 날짜 표기는 `2026-10-05 (월)` 형식입니다.
